本博客基于 Vue 3 + Vite + vite-ssg 自实现主题,前端样式参考了 Hexo 的 **闪烁之狐(Flicker Fox)** 主题(主打封面展示、侧边目录、置顶文章等),所以 front-matter 字段沿用了闪烁之狐的命名习惯。部署在 GitHub Pages,通过 GitHub Actions 全自动构建。

整个发布流程可以浓缩成一句话:**在语雀写好文章 → 导出 Markdown → 放进项目 → git push,剩下的事 GitHub Actions 自动搞定**(图片下载、构建、部署一并完成)。

<br>

## 一、整体流程

```
1. 在语雀写完一篇文章
2. 语雀右上角 ··· → 导出 → Markdown,得到一个 .md 文件
3. 把 .md 文件放进 src/content/posts/ 目录,补/调整 front-matter
4. (可选) 本地预览:npm run dev → http://127.0.0.1:5173/
5. git push
6. GitHub Actions 自动:
   prebuild → scripts/sync-yuque.mjs(下载语雀图 + 改写 URL)
   build    → vite-ssg 生成静态文件 + RSS + 站点地图
   verify   → 检查 index.html / rss.xml / sitemap.xml
   deploy   → 部署到 GitHub Pages
```

最简版本就是 **前 5 步**,其他都是辅助。

<br>

## 二、详细步骤

### 步骤 1:在语雀写好文章

登录 [语雀](https://www.yuque.com),在知识库下新建文档,正常写作。图片直接拖入语雀编辑器,语雀会上传到自己的 CDN(`cdn.nlark.com`)。

> 图片不用先下载到本地 —— **下一步的脚本会自动处理**。

<br>

### 步骤 2:导出为 Markdown

文章写完后,语雀文档页面右上角 `···` → `导出` → `Markdown`,浏览器会下载一个 `.md` 文件。

导出的文件内容大致长这样:

```markdown
---
title: 我的文章标题
---

正文开始,里面图片的 URL 是这样的:

![描述](https://cdn.nlark.com/yuque/0/2025/xxx/1768140135121-xxx.webp)
```

> 图片 URL 还是 `cdn.nlark.com` 的远程地址,**先不用动它**,push 之后 prebuild 步骤会自动下载到项目本地并改写路径。

<br>

### 步骤 3:放进项目对应目录

把导出的 `.md` 文件移动到 `src/content/posts/` 目录下:

```
src/content/posts/
  ├── 华南植物园.md
  ├── 2025我的年度总结.md
  └── 新文章.md                 ← 新建的就是这个
```

**文件名建议**:

- 简短、描述性,不要带空格(用 `-` 替代)
- 中文或英文都行,系统会自动 URL 编码
- 例:`react-19-新特性.md` 比 `React 19 新特性.md` 更稳
- 文件名就是 URL 的一部分(slug),发布后无法轻易更改,**取名要慎重**

<br>

### 步骤 4:补 / 调整 front-matter

从语雀导出的 md 顶部可能只有 `title` 一个字段,需要手动补充其他字段。完整模板如下(参考闪烁之狐主题的写法,本项目大部分字段会生效):

```markdown
---
title: 2025我的年度总结
date: 2026-01-01 16:11:03
tags: ["2025年", "年度总结"]
categories: ["年度总结"]              # 文章分类(数组格式)
author: "刺槐儿"                     # 作者名(闪烁之狐会显示,本项目不解析)
toc: true                            # 是否显示目录(闪烁之狐支持,本项目默认就有)
comments: true                       # 是否开启评论(本项目未集成评论系统)
cover: /images/cover.webp            # 文章封面图(关键!闪烁之狐主打封面展示)
top: true                            # 是否置顶文章(可选)
description: 一句话简介,显示在首页卡片摘要(选填)
---
```

<br>

### 步骤 5:本地预览(强烈建议)

```bash
npm run dev
# 打开 http://127.0.0.1:5173/
```

要确认的几个点:

- 首页能看到新文章卡片,封面图正常显示
- 点进去能打开详情页,正文图片正常加载
- PC 宽屏左侧能看到自动生成的目录(从 `##` / `###` 提取)
- 代码块高亮(基于 Shiki)
- `Ctrl + K` 搜索能找到标题

预览 OK 再 push。

<br>

### 步骤 6:提交并推送

```bash
git add src/content/posts/新文章.md
git commit -m "post: 新文章标题"
git push
```

> 如果改了别的文件(比如加了图、改了 `src/utils/site.ts`),都一起 add:
> ```bash
> git add .
> git commit -m "post: 新文章标题"
> git push
> ```

<br>

### 步骤 7:等自动部署

1. 打开 https://github.com/liangyoubiao/liangyoubiao.github.io/actions
2. 看 "Build & Deploy to GitHub Pages" workflow 跑(1~3 分钟)
3. 绿色 ✅ 后,访问 https://liangyoubiao.github.io 即可看到新文章

<br>

## 三、front-matter 字段详解

### 字段生效对照表

| 字段           | 闪烁之狐 | 本项目 | 说明                                                              |
| -------------- | -------- | ------ | ----------------------------------------------------------------- |
| `title`        | ✅       | ✅     | 文章标题                                                          |
| `date`         | ✅       | ✅     | `YYYY-MM-DD HH:mm:ss`,**决定 URL 路径**:`/YYYY/MM/DD/slug/`       |
| `tags`         | ✅       | ✅     | 数组,影响标签页和归档分类                                        |
| `categories`   | ✅       | ✅     | 数组或字符串,影响分类页                                          |
| `author`       | ✅       | ❌     | 闪烁之狐显示作者名,**本项目不解析,写了也不会显示**               |
| `toc`          | ✅       | ❌     | 闪烁之狐控制目录显示,**本项目默认就有目录,开关无效**             |
| `comments`     | ✅       | ❌     | 闪烁之狐控制评论,**本项目目前没有评论系统,开关无效**             |
| `cover`        | ✅       | ✅     | 封面图路径                                                       |
| `top`          | ✅       | ✅     | `true` 时进首页"推荐文章"区                                       |
| `keywords`     | ✅       | ❌     | SEO 关键词,**本项目不解析**                                       |
| `description`  | ✅       | ✅     | 自定义摘要;不填则从正文前 90 字符自动截取                          |

> **从语雀 / 其他闪烁之狐博客迁移过来的文章,所有字段都可以原样保留**——本项目只解析生效的字段,其余字段会被静默忽略,不会报错。

<br>

### `date` 时间格式

- `2026-08-22 14:30:00` 没有时区后缀 → 按 **Asia/Shanghai 本地时间** 解析
- 实际存的是 UTC(2026-08-22 06:30 UTC)
- URL 路径**按本地日期**生成:`/2026/08/22/...`,所以填本地时间就对了
- 不要写未来时间 —— 首页按发布时间倒序,未来时间会排到最后

<br>

### `cover` 封面图三种用法

```yaml
# 选项 A:用系统自带池(24 张图任选)
cover: /medias/featureimages/3.webp     # 0~23 任一

# 选项 B:用自定义封面(放 public/images/ 下)
cover: /images/cover.webp                # 推荐 1280×720 的 WebP

# 选项 C:不填 cover
# 系统先按 slug 哈希从池里自动选一张,客户端每次刷新会随机抽正文里的内联图片
# 什么都不写,适合没特别想法的时候
```

封面图推荐 **WebP 格式、1280×720**,放在 `public/images/` 下。

<br>

### `top` 置顶

```yaml
top: true   # 进首页"推荐文章"区,会显示在 Banner 下方的卡片位
top: false  # 普通文章(默认)
```

<br>

### `description` 摘要

```yaml
description: 一句话简介,显示在首页卡片摘要
```

不填的话,系统会自动从正文前 90 个字符截取作为摘要。

<br>

## 四、图片自动同步(全自动)

`scripts/sync-yuque.mjs` 是 `npm run build` 的 prebuild 钩子的一部分,**每次 push 都会自动执行**:

1. 扫 `src/content/posts/*.md` 里 `cdn.nlark.com` 的图片
2. **每篇 md 一份**,下载到 `public/images/yuque/<md文件名>/<图片文件名>`
3. 把 md 里的远程 URL 一次性改写为 `/images/yuque/<md文件名>/<图片文件名>`
4. 幂等:已下载的图跳过,URL 替换后稳定

也就是说 **从语雀导出的 md 直接 commit push 就行,图片处理全自动**:

```bash
# md 里图片 URL 还是 https://cdn.nlark.com/yuque/...
git add src/content/posts/新文章.md
git commit -m "post: 新文章"
git push
# GitHub Actions 跑:
#   prebuild → 下载到 public/images/yuque/新文章/、改写 URL
#   build    → vite-ssg + rss + sitemap
#   deploy   → GitHub Pages
```

<br>

**手动跑(调试时用)**:

```bash
node scripts/sync-yuque.mjs
# 或
npm run sync:images
```

<br>

**不是从语雀来的图**(自己拍的照片、截图等):放在 `public/images/` 下,按主题分子目录(如 `public/images/travel/`、`public/images/code/`),正文里直接引用:

```markdown
![描述](/images/travel/photo.webp)
```

> 路径以 `/` 开头,vite-ssg 会从 public 目录读取。

<br>

**目录结构示意**:

```
public/
  ├── images/                            # 自己加的图(按主题分子目录)
  │   ├── cover.webp                     # 自定义封面示例
  │   ├── travel/
  │   └── code/
  ├── images/yuque/                      # 语雀图(自动同步,按 md 文件名分子目录)
  │   ├── 华南植物园/
  │   │   └── 1789911xxxx-xxx.jpeg
  │   └── 2025我的年度总结/
  │       └── 1768140xxxx-xxx.webp
  └── medias/featureimages/              # 系统封面池(0~23.webp,共 24 张)
```

<br>

## 五、进阶用法

### 修改已有文章

直接编辑 `src/content/posts/<文件名>.md`,改完 commit push,几分钟内线上更新。

<br>

### 删除文章

```bash
git rm src/content/posts/要删的.md
git commit -m "chore: 删除旧文"
git push
```

<br>

### 草稿(本地预览但不发布)

直接新建 md 文件,本地 `npm run dev` 看,改好再 push。**没有专门的草稿模式开关**。

<br>

## 六、常见问题

### Q:文章不显示在首页?

- 检查 `date` 是不是未来时间 —— 首页按发布时间倒序,未来时间排到最后
- 检查文件是否在 `src/content/posts/` 路径下
- 清浏览器缓存试一下

<br>

### Q:推送后 GitHub Actions 失败?

看 Actions 日志,最常见:

- `npm ci` 失败 → `package-lock.json` 损坏,删了重 `npm install`
- `sh: command not found` → workflow 文件被破坏
- `Cannot find module` → 依赖缺失

<br>

### Q:图片加载不出来?

- 第一次 push 走自动同步要等 prebuild 跑完
- 检查 `public/images/yuque/<md文件名>/` 下是否真的有这张图
- 语雀源站删除 / 迁移过的图会下载失败,build 会继续但那几张会 404

<br>

### Q:代码块不高亮?

- 用了三个反引号 + 语言名:` ```typescript `
- 已支持的语言见 `src/utils/markdown.ts` 的 `COMMON_LANGS`
- 没在列表的语言回退到 `plaintext`

<br>

### Q:文章目录(TOC)不显示?

- 文章至少要有一个 `##` 或 `###` 标题才会生成 TOC
- 屏幕 < 1100px 会自动隐藏(右侧空间不够)

<br>

### Q:搜索搜不到刚发的文章?

- `npm run build` 时会自动跑 `build-search.mjs` 生成 `public/search-data.json`
- 推完 search-data.json 才会更新索引
- 等下一次 push 就有了(或者 `git add public/search-data.json` 单独 commit)

<br>
