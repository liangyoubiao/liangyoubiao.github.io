# 如何在个人博客上发布一篇文章

> 完整流程:从语雀导出 Markdown,到博客上线。本项目基于 Vue 3 + Vite + vite-ssg,部署在 GitHub Pages。

## 流程总览

```
1. 在语雀写完 → 导出为 Markdown(图片留在语雀 CDN 上)
2. 放进 src/content/posts/ 目录,补/调 front-matter
3. (可选) 本地预览 npm run dev
4. git push
5. GitHub Actions 自动:
   prebuild → sync-yuque.mjs(下载图片 + 改写 URL)
   build    → vite-ssg + rss + sitemap
   deploy   → GitHub Pages
```

最简版本就是 **第 1 步到第 4 步**,其他都是辅助。

---

## 第 1 步:从语雀导出 Markdown

在语雀文档页面右上角 `···` → `导出` → `Markdown`,下载到本地,得到一个 `.md` 文件。

导出的文件长这样:

```markdown
---
title: 我的文章标题
---

正文开始,里面图片的 URL 是这样的:

![描述](https://cdn.nlark.com/yuque/0/2025/xxx/1768140135121-xxx.webp)
```

图片 URL 还是 `cdn.nlark.com` 的远程地址,**先不用动它**——下一步的脚本会自动下载到本地。

---

## 第 2 步:放进项目

把导出的 `.md` 文件移动到 `src/content/posts/` 目录下,文件名就是 URL 的一部分(slug):

```
src/content/posts/
  ├── 华南植物园.md              ← 例
  ├── 2025我的年度总结.md        ← 例
  └── 新文章.md                  ← 新建这个
```

### 文件名建议

- 简短、描述性,不要带空格(用 `-` 替代)
- 中文或 ASCII 都行,都会 URL 编码
- 例:`react-19-新特性.md` 比 `React 19 新特性.md` 更稳

---

## 第 3 步:补 front-matter

导出的 md 顶部可能只有 `title`,需要按下面模板补全:

```markdown
---
title: 我的新文章
date: 2026-08-22 14:30:00
tags: [生活, 思考]
categories: [随笔]
cover: /medias/featureimages/0.webp
top: false
description: 一句话简介,会显示在首页卡片摘要(选填)
---

正文从这里开始
```

### 字段说明

> 本项目只解析下面这几个字段(`src/utils/posts.ts` 的 `PostMeta`)。
> 其他主题(比如 hexo 闪烁之狐)的 `author` / `toc` / `comments` 等字段**写了也没用**,直接忽略。

| 字段           | 必填 | 说明                                                                                                  |
| -------------- | ---- | ----------------------------------------------------------------------------------------------------- |
| `title`        | ✅   | 文章标题                                                                                              |
| `date`         | ✅   | `YYYY-MM-DD HH:mm:ss`,**决定 URL 路径**:`/YYYY/MM/DD/slug/`                                          |
| `tags`         | ⭕   | 数组,影响标签页和归档分类                                                                            |
| `categories`   | ⭕   | 数组或字符串,影响分类页                                                                              |
| `cover`        | ⭕   | 封面图路径(`/medias/featureimages/N.webp` 从系统池选;或自己指定如 `/images/cover.webp`)               |
| `top`          | ⭕   | `true` 时进首页「推荐文章」区                                                                         |
| `description`  | ⭕   | 自定义摘要;不填则从正文前 90 字符自动截取                                                             |

### 关于 `date` 的时间格式

- `2026-08-22 14:30:00` 没有时区后缀 → 按 **Asia/Shanghai 本地时间** 解析
- 实际存的是 UTC(2026-08-22 06:30 UTC)
- URL 路径**按本地日期**生成:`/2026/08/22/...`,所以填本地时间就对了

### 关于 `cover` 封面图

三种用法:

```yaml
# 选项 A:用系统自带池(24 张图任选)
cover: /medias/featureimages/3.webp     # 0~23 任一

# 选项 B:不填 cover,系统按 slug 哈希从池里自动选一张
# (什么都不写,适合没特别想法的时候)

# 选项 C:用自定义封面
cover: /images/我的封面.webp
```

封面图推荐 WebP、1280×720,放 `public/images/` 下。改图片建议跑 `node scripts/compress-images.mjs` 重新生成 `src/__generated_routes.ts`。

## 第 4 步:本地预览(强烈建议)

```bash
npm run dev
# 打开 http://127.0.0.1:5173/
```

要看的几个点:

- 首页能看到新文章卡片
- 点进去能打开详情页,图片正常加载
- 左侧文章目录(PC 宽屏)显示从 `##` / `###` 提取的标题
- 代码块高亮(Shiki)
- 搜索(`Ctrl+K`)能找到标题

预览 OK 再 push。

## 图片处理专题

### 语雀图自动同步(推荐,全自动)

`scripts/sync-yuque.mjs` 是 `prebuild` 钩子的一部分,跑 `npm run build` 前会自动执行:

1. 扫 `src/content/posts/*.md` 里 `cdn.nlark.com` 的图
2. **每篇 md 一份**,下载到 `public/images/yuque/<md文件名>/<图片文件名>`
3. 把 md 里的远程 URL 一次改写为 `/images/yuque/<md文件名>/<图片文件名>`
4. 幂等:已下载的图跳过,URL 替换一次后稳定

也就是说从语雀导出的 md 直接 commit push 就行,图片处理全自动:

```bash
# md 里图片 URL 还是 https://cdn.nlark.com/yuque/...
git add src/content/posts/新文章.md
git commit -m "post: 新文章"
git push
# GitHub Actions 跑:
#   prebuild → 下载到 public/images/yuque/新文章/、改写 URL
#   build    → vite-ssg + rss + sitemap
#   deploy   → GitHub Pages
```

**调试时手动跑**:

```bash
node scripts/sync-yuque.mjs
# 或
npm run sync:images
```

**容错**:

- 下载失败的图跳过,build 仍能继续(失败那几张会 404,需手动补图)
- 第一次 push 可能耗时几十秒;之后 push 瞬间完成(URL 已替换,文件未变)
- 没有语雀图的 md 不建立子目录,不会留空目录

### 手动放图(不从语雀来的)

放在 `public/images/` 下,自己起子目录按主题分类(比如 `public/images/travel/`、`public/images/code/`)。

正文里引用:

```markdown
![描述](/images/travel/photo.webp)
```

> 路径以 `/` 开头,这样 vite-ssg 会从 public 目录读取。

### 目录结构示意

```
public/
  ├── images/                            # 自己加的图(按主题分子目录)
  │   ├── travel/
  │   └── code/
  ├── images/yuque/                      # 语雀图(自动同步,按 md 文件名分子目录)
  │   ├── 华南植物园/
  │   │   └── 1789911xxxx-xxx.jpeg
  │   └── 2025我的年度总结/
  │       └── 1768140xxxx-xxx.webp
  └── medias/featureimages/              # 系统封面池(0~23.webp)
```

## 进阶用法

### 置顶文章(进「推荐文章」)

```yaml
top: true
```

### 草稿(本地预览但不发布)

直接新建 md 文件,本地 `npm run dev` 看,改好再 push。没有专门的草稿模式开关。

### 修改已有文章

直接编辑对应的 `.md` 文件,改完 commit push,几分钟内线上更新。

### 删除文章

```bash
git rm src/content/posts/要删的.md
git commit -m "chore: 删除旧文"
git push
```

## 常见问题

### Q: 文章不显示在首页?

- 检查 `date` 是不是未来时间 —— 首页按发布时间倒序,未来时间排到最后
- 检查 `src/content/posts/` 路径正确
- 清浏览器缓存试一下

### Q: 推送后 GitHub Actions 失败?

看 Actions 日志,最常见:

- `npm ci` 失败 → `package-lock.json` 损坏,删了重 `npm install`
- `sh: command not found` → workflow 文件被破坏
- `Cannot find module` → 依赖缺失

### Q: 图片加载不出来?

- 第一次 push 走自动同步要等 prebuild 跑完,本地 dev 直接看 dist 不会有图
- 检查 `public/images/yuque/<md文件名>/` 下是否真的有这张图
- 语雀源站删除/迁移过的图会下载失败,build 会继续但那几张会 404

### Q: 代码块不高亮?

- 用了三个反引号 + 语言名:` ```typescript `
- 已支持的语言见 `src/utils/markdown.ts` 的 `COMMON_LANGS`
- 没在列表的语言回退到 `plaintext`

### Q: 文章目录(TOC)不显示?

- 文章至少要有一个 `##` 或 `###` 标题才会生成 TOC
- 屏幕 < 1100px 也会自动隐藏(右侧空间不够)

### Q: 搜索搜不到刚发的文章?

- `npm run build` 时会自动跑 `build-search.mjs` 生成 `public/search-data.json`
- 推完 search-data.json 才会更新索引
- 等下一次 push 就有了(或者 `git add public/search-data.json` 单独 commit)
